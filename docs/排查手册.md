# 排查手册（调试期专用）

> 目的：**你遇到任何问题，把「报错信息 + 日志/诊断包」发过来，就能快速定位。**
> 本项目处于实操测试阶段，默认开启 `debug` 日志，所有关键路径都埋了稳定的「标记」。

---

## 一、最快的三步

**方式 A（推荐，网页点一点）**：打开 `http://<服务器IP>:8080/report`（侧边栏「**问题反馈**」）

1. 点「**一键下载诊断报告**」→ 下载 `ttdownload-report-*.zip`
2. 页面下方可看「最近失败的任务」及原因（有「复制」按钮）
3. 把 zip + 报错截图发我

**方式 B（命令行）**：

```bash
sudo ./deploy.sh --status                      # 1) 服务状态 + 健康检查
sudo ./deploy.sh --logs                        # 2) 最近 200 行日志（--logs 2000 看更多）
curl -OJ http://127.0.0.1:8080/api/system/report  # 3) 一键报告 zip
```

**方式 C（服务起不来、网页打不开时）——离线收集**：

```bash
cd ttdownload-web
sudo ./deploy.sh --collect      # 不需要服务在运行，直接把日志打包到当前目录
# → ttdownload-logs-<时间>.zip（app.log / 轮转日志 / deploy.log / app.db）
sudo ./deploy.sh --logs 500     # 同时看看最后 500 行日志
systemctl status ttdownload-web --no-pager
```

报告 zip 里有什么：

| 文件 | 内容 |
| --- | --- |
| `README.txt` | 怎么用这份报告 + 隐私说明 |
| `errors.log` | **先看这个**：只保留 WARN/ERROR 与失败相关标记的摘要 |
| `app.log` / `app.log.N` | 完整应用日志（含轮转历史，每个最多 2MB 尾部） |
| `deploy.log` | 部署/更新脚本的全部输出 |
| `diagnostics.json` | 运行环境 / 生效配置（密钥打码）/ 磁盘 / 工具版本 / 事件 |
| `system-info.json` | 磁盘、数据库、各外部工具版本 |
| `tasks.json` | 任务状态统计 + 每个失败任务的错误原因与重试次数 |
| `network.json` | 网络自检逐项结果（DNS/HTTPS/yt-dlp/YouTube/CDN/RPC） |
| `markers.json` | 日志标记说明表（`[MARK:XXX]` 的含义） |

然后把 **① 报错截图/文字 + ② 这个 zip（或 `errors.log` + `app.log`）** 发我。
诊断包里已经包含：应用与运行环境、配置（密钥已脱敏）、全部日志文件尾部、任务列表与失败原因、
外部工具可用性、磁盘状态、**网络自检结果**、以及标记说明表 —— 通常不需要你再补别的。

## 二、日志在哪、怎么看

| 内容 | 位置 |
| --- | --- |
| 应用日志 | `/ttdownload/state/app.log`（>20MB 轮转为 `app.log.1` … 保留 5 个） |
| 部署脚本日志 | `/ttdownload/state/logs/deploy.log` |
| systemd 日志 | `journalctl -u ttdownload-web -n 200 --no-pager` |
| 网页查看 | 「日志」页：调试开关、级别过滤、标记过滤、关键字搜索、下载、清空、导出诊断包 |

常用命令：

```bash
sudo ./deploy.sh --logs             # 最近 200 行
sudo ./deploy.sh --logs-follow      # 实时跟踪
sudo ./deploy.sh --logs 2000        # 最近 2000 行
grep 'MARK:TASK_FAIL' /ttdownload/state/app.log
```

### 日志长什么样

```
2026-09-11T14:20:38.952Z [INFO ] [MARK:TASK_CREATE] [webvideo] 公开视频任务已入队 #12 :: {"url":"...","formatId":"137"}
2026-09-11T14:20:40.113Z [INFO ] [MARK:YTDLP_ATTEMPT] [task#12>ytdlp] 尝试方式 1/9：指定格式 :: {"bin":"yt-dlp","args":["-J",...]}
2026-09-11T14:20:44.501Z [WARN ] [task#12>ytdlp] [MARK:YTDLP_EXIT] 方式「指定格式」失败 code=1（4388ms）：...
```

- `[INFO ]/[WARN ]/[ERROR]/[DEBUG]/[TRACE]`：级别
- `[MARK:XXX]`：**标记**，grep 的锚点
- `[task#12>ytdlp]`：作用域（哪个任务、哪个子模块）
- `:: {...}`：结构化细节（argv、退出码、耗时、错误摘要；密钥自动脱敏）

## 三、标记对照表（网页「日志」页也会列出）

| 标记 | 记录什么 | 什么时候看它 |
| --- | --- | --- |
| `BOOT` | 启动/关闭、版本、运行环境 | 服务起不来、重启后确认版本 |
| `CONFIG` | 生效配置（目录/端口/并发/保留空间/工具路径） | 配置没生效、路径不对 |
| `HTTP_REQ` / `HTTP_RES` | 每个请求：方法/路径/来源/状态码/耗时 | 页面 404、接口 500、请求慢 |
| `HTTP_ERR` | HTTP 处理异常（含堆栈） | 接口报错 |
| `DISK_GATE` | 空间门控数值（free/reserve/reserved/usable/need） | 任务一直「等待中」 |
| `SCHED_TICK` | 每轮调度摘要（等待/运行/可用空间） | 队列不动、并发不符合预期 |
| `TASK_CREATE` | 任务创建（模块/URL/格式） | 任务没进队列 |
| `TASK_STATE` | 状态流转/暂停/继续/恢复 | 状态卡住 |
| `TASK_FAIL` | 失败原因、是否永久错误、重试次数 | 任务失败（**最常看**） |
| `TASK_RETRY` | 自动重试（第 N/总 次） | 为什么还在重试 |
| `SPACE_FREED` | 空间腾挪广播（释放多少、原因） | 删除后等待队列没有立刻动 |
| `YTDLP_PARSE` | `yt-dlp -J` 完整 argv、输出大小、失败原因 | 解析失败/受限 |
| `YTDLP_ATTEMPT` | 策略阶梯第几种方式、完整 argv、cookies 情况 | 在线视频下载失败（**最常看**） |
| `YTDLP_EXIT` | 单次尝试退出码、耗时、stderr 摘要 | 看某一种方式为什么失败 |
| `YTDLP_DONE` | 产物文件与大小、用了几种方式、总耗时 | 下载成功但没有文件 |
| `NET_CHECK` | 网络自检每一项结果 | 怀疑网络 |
| `ARIA2_RPC` | aria2 JSON-RPC 调用与错误 | aria2 任务失败 |
| `ARIA2_DAEMON` | aria2c 守护进程拉起（含完整参数） | aria2 起不来 |
| `TR_RPC` | transmission RPC（409 协商、认证、结果） | BT 报 401/409 |
| `ANDROID` | 安卓端每个请求（鉴权方式、UA） | App 连不上/401 |
| `PIPELINE` / `ARCHIVE` / `ENCRYPT` / `PUBLISH` | 归档→加密→发布每一步 | 卡在归档/加密、成品没出现 |
| `CLEANUP` | 上报完成后的删除 | 文件没被删掉 |
| `BT_EVICT` / `BT_CLEANUP` | 出清判定细节与目录清理（含释放字节） | BT 任务被清掉的原因 |
| `SETTINGS` | 设置更新（改了哪些字段） | 设置没生效 |
| `PROC_SPAWN` / `PROC_EXIT` | **所有**外部命令的 argv/退出码/耗时/stdout+stderr 摘要 | 任何外部命令相关疑难 |
| `TOOL_STATUS` | 外部工具探测（`--version`） | 工具没装/路径错 |
| `DIAG` | 日志下载、清空、诊断包导出 | 确认导出是否成功 |
| `ERROR` | 未捕获异常/兜底错误（含堆栈） | 服务异常 |

## 四、按现象找原因（速查）

### 1. 任务一直「等待中」
```bash
grep 'MARK:DISK_GATE' /ttdownload/state/app.log | tail -20
```
看 `usableBytes` 与 `needBytes`：`usable = free - reserve(默认10GiB) - 运行中任务预留`。
- `usable` 为负 → 清 `xiaofeizhe_downd/` 或调小 `RESERVE_FREE_BYTES`
- `usable` 够但没启动 → 看 `moduleConcurrency`（每模块并发）与 `maxConcurrent`
- `BT` 任务还要看 `transmission` 是否可用

### 2. 在线视频失败（会员/登录/区域/CDN）
```bash
grep 'MARK:YTDLP' /ttdownload/state/app.log | tail -40
```
日志里有**每一种尝试的完整命令行 + stderr**。对照：
- 出现 `members-only`/`Sign in` → 需要 cookies（设置 → 公开视频）
- 出现连接超时/403 → 在「设置 → 公开视频」填 `--proxy ...`
- 首页「网络自检」面板会直接告诉你 DNS/YouTube/CDN 哪一环断了

### 3. BT 模块报 RPC 错误
```bash
grep 'MARK:TR_RPC' /ttdownload/state/app.log | tail -20
```
- `401` → 用户名/密码不对（脚本安装固定用户 `opengl`）
- `409` 反复 → 会话协商失败，通常也是认证或白名单问题
- 连接被拒 → `systemctl status transmission-daemon`

### 4. 安卓 App 报 401 / 拉不到清单
```bash
grep 'MARK:ANDROID' /ttdownload/state/app.log | tail -30
```
对比 `.env` 的 `ANDROID_TOKEN` 与 App 里填的 Token；确认端口放行（`ufw allow 8080`）。

### 5. 归档/加密/发布卡住
```bash
grep -E 'MARK:(PIPELINE|ARCHIVE|ENCRYPT|PUBLISH)' /ttdownload/state/app.log | tail -40
```
看是哪一步没有后续日志；`PROC_EXIT` 里会有 `zip`/`openssl` 的 stderr。

### 6. 部署/更新失败
```bash
tail -100 /ttdownload/state/logs/deploy.log
```
常见：GitHub 连不上（DNS/代理）、`npm ci` 失败（网络或磁盘满）、端口被占、`git pull` 有本地改动冲突。

## 五、发给我什么最有用

1. **诊断报告**：网页「问题反馈」页 → 「一键下载诊断报告」，或 `curl -OJ http://127.0.0.1:8080/api/system/report`
   （若想更小：只下「错误日志摘要」`errors.log`）
2. **现象描述**：点了什么、期望什么、实际什么（越具体越好）
3. **时间点**：大概几点几分出的问题（方便在长日志里定位）
4. 如果报告太大发不出，退而求其次：
   ```bash
   # 只发失败相关
   grep -E 'MARK:(TASK_FAIL|TASK_RETRY|YTDLP|TR_RPC|ARIA2_RPC|HTTP_ERR|ERROR)' /ttdownload/state/app.log | tail -500 > /tmp/err.log
   # 再带上最近 500 行完整上下文
   tail -500 /ttdownload/state/app.log > /tmp/tail.log
   ```
5. 前端问题：浏览器 F12 的 Console/Network 截图（面板会用红色 toast 提示接口错误）

> 隐私说明：诊断包里的 `ANDROID_TOKEN`、RPC 密码、加密密码等都会被替换成 `***`；
> 但日志中可能包含**视频 URL / 种子名称**，如果你介意可以先自行删掉对应行。
